### 关键架构决策 (ADR)
1. **ADR-001**: Flutter + Platform Channel 跨平台方案（UI 复用率 ~85%）
2. **ADR-002**: Android 双引擎 = AccessibilityService 主 + NotificationListener 辅
3. **ADR-003**: iOS 只能走 Notification Service Extension + App Group，功能阉割（无法自动跳转/@）
4. **ADR-004**: Drift(SQLite) + SQLCipher 本地加密存储，E2EE 云同步可选
5. **ADR-005**: 微信 UI 适配规则声明式 YAML 热更新（应对微信改版）

### 核心风险
- iOS 平台能力严重受限（无法监听界面、无法自动跳转）→ 定位"Android 完整 + iOS 提醒"
- 微信 UI 改版导致监听失效 → 规则热更新机制
- 合规红线：不做协议逆向/hook，定位"辅助工具"

### 24 个月演进路线
P1 MVP(Android) → P2 双端+iOS阉割 → P3 AI语义匹配 → P4 云同步/团队版 → P5 SaaS生态

## 2026-07-31 续：自动回复探索 → 转向智能复制+快捷话术

### 原计划
按架构 ADR-002 用 AccessibilityService 实现自动回复（唤起微信→搜索群→进群→@发送人→发送）。完成 spec（docs/superpowers/specs/2026-07-31-auto-reply-design.md）+ plan，开始实施 Phase A/B（领域层 + 基础设施，已测试）。

### 重大发现：微信 8.0.76 屏蔽 AccessibilityService（已验证，非推测）
对照实验（同一 service/同设备/同运行）：
- 华为应用市场（普通 App）→ AccessibilityService 拿到完整节点树（childCount=5，text/id/bounds 全可见）
- 微信 8.0.76 → 空根节点（childCount=0，无子节点）
→ 微信主动屏蔽非系统签名 app 的无障碍节点读取。基于节点查找+点击的自动回复链路完全不可行。
uiautomator 也被 secure flag 阻断。Root/Xposed/协议逆向是合规红线不做。
详见 docs/wechat-accessibility-finding.md。

### 转向：智能复制 + 快捷话术
用户确认改做：不碰微信界面操作，把回复辅助做到极致。
- 智能复制：详情页点"回复"→选话术→自动组装 `@发送人 话术` 复制到剪贴板 + 唤起微信，用户粘贴即发。
- 多快捷话术：预设"接单/已发车/稍后联系/已满"，详情页 sheet 选择，设置页增删改、设默认、自定义。
- Phase A/B 的 AutoReply 代码保留为预留（未来微信防护变化可启用）。

- 详情页 reply_sheet.dart（话术选择 + 自定义）+ 设置页话术管理区
